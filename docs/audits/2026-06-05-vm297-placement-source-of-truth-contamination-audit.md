## Source-Of-Truth Contract Checked

`research/build-faction-artifacts.mjs` reads `data/raw-factions/*/*.profile.json`, `data/raw-factions/*/*.placement.json`, `data/identity-layers.json`, and current `data/factions.json`, then writes `data/factions.json`, `data/placement-model.json`, `data/placement-model.schema.json`, and `supabase/functions/guild-recruiter/faction-context.ts`.

Placement model fields are generated from raw sources:

- `identity.mechanics` comes from raw profile mechanics fields.
- `placement_axes` comes from raw placement `calibration_tuning`.
- `good_fit_indicators`, `poor_fit_indicators`, discriminator questions, collision guidance, and chatbot guidance come from raw placement fields.
- `source_metadata.profile_version` comes from raw profile version fields.
- `source_metadata.claim_count` comes from raw profile claim IDs, not the generated artifact.

Therefore, direct placement edits in `data/placement-model.json` are generated-only unless the raw placement/profile files already contain the same state.

## Build Preservation Risk

The approved builder was not run in VM-297 because this dirty worktree already contains broad unrelated generated and runtime changes. Running the builder here would mutate `data/factions.json`, `data/placement-model.json`, `data/placement-model.schema.json`, and Supabase context, making it unsafe to distinguish audit evidence from new generated drift.

Static builder inspection is enough to classify the risk:

- Jeskai `data/placement-model.json` VM-294 changes would be erased or downgraded because raw Jeskai calibration axes and discriminator details are empty.
- Witch `data/placement-model.json` VM-295 changes would be erased or downgraded because raw Witch calibration axes and discriminator details are empty, and raw Witch remains non-live/not placement-eligible in the VM-267 packet.
- Mardu `data/placement-model.json` VM-296 changes would partially revert to older raw calibration and empty discriminator details, because raw Mardu still has the older source state.
- `data/factions.json` display copy may survive a build because the builder preserves existing display data, but that makes it display-copy persistence, not source evidence.
- `data/archscry-flavor-snippets.json` was not evaluated through its generator in VM-297; focused tests already identify Witch and Jeskai risks.
