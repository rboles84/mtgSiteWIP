### Impact

The current wording can be read as authorization to remove or rename numeric internals and serialized result fields rather than add an honest presentation layer. That interpretation could break ranking, adaptive stopping, persistence, OAuth return, legacy normalization, saved readings, dossier rendering, adjacent views, recommendations, deck links, and Maze handoffs. It could also mistakenly alter the authored Mana Alignment Matrix while trying to remove uncalibrated public confidence.

Because the owner explicitly requires additive compatibility before Gate A implementation planning, this is a material audit-requirement defect rather than lower-value wording polish.

### Expected boundary

Gate A must explicitly:

- apply removal only to public confidence, certainty, accuracy, probability, and strength claims;
- preserve internal scores, softmax shares, gaps, and ranking inputs for current model operation and legacy compatibility;
- preserve existing serialized field names and shapes unless a separately reviewed additive version/migration contract exists;
- add explicit result-state fields for tied, close, insufficient, mixed, contradictory, invalid, and incomplete outcomes;
- keep Mana Alignment Matrix authored identity values separate from confidence percentages and placement-score internals;
- require a complete field-level writer/reader/serialization/render/persistence/handoff consumer map before Gate A implementation planning.
