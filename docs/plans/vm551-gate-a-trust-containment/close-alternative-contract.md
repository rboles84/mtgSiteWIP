# Close-Alternative Contract

## Meaning

`adjacent_matches` currently serializes numerical ranks two and three. It is not evidence of philosophical, color, behavioral, or mechanical adjacency. Gate A preserves the field and every reader but changes public interpretation.

Public term: **Close alternative**.
Reserved term: **Adjacent identity** only after a separately reviewed semantic-adjacency contract; none is implemented in Gate A.

## Eligibility

| Case | Gate A public behavior |
|---|---|
| Exact top tie | Present both identities as co-leaders. The other leader is not called an alternative or adjacent. Hide rank three. |
| Owner-approved close rule passes | Show rank two once as Close alternative. Explain its direct supporting answer observation. Do not show its numeric share/band. |
| Rank two exists but close rule fails/unknown | Omit the alternative card, summary-strip slot, terminal affinity line, and alternative-view link. Preserve data internally. |
| Rank two has no direct positive evidence trail | Omit. Do not turn suppression, color fallback, or generic identity similarity into positive support. |
| Rank three | Never public in Gate A. Preserve in `top_matches`/`adjacent_matches` and tests. |
| Mixed/contradictory explicit state | Show only identities named by that state contract; do not auto-promote rank order. |
| Insufficient/unknown/invalid/incomplete | No close alternative unless an explicit compatible historical state safely names it; default omit. |

Recommended close heuristic is limited to a completed result with known top two, direct positive rank-two evidence, and final `confidence_gap` at/below the already-authored Crucible comparison value after the Crucible/terminal stopping path. This reads existing outputs only. Owner may choose the safer default of no automatic close alternatives.

## Tiny-share protection

- Never display share, percentage, meter, or strong/moderate/emerging label.
- Never call rank two “strong,” “meaningful,” or “recognized” based on its absolute share.
- Require the approved relative rule and direct positive trail; otherwise omit.
- Do not invent an absolute cutoff, because the softmax shares are not calibrated and differ across a 37-identity field.
- If future pilot evidence supports an absolute/evidence-quality contract, that is Gate B1 or later.

## Alternative view behavior

“View this fit” becomes **Compare this alternative**. The action must:

1. keep `APP_STATE.activeResult` and serialized `faction` unchanged;
2. change only the active viewed identity;
3. retain a persistent “Back to original reading” control;
4. retain the result-state/close limitation in the alternative view;
5. render the alternative’s authored Matrix profile without changing either Matrix source;
6. scope recommendations/deck links/Maze context to the viewed identity while retaining original primary context in the stored result/handoff;
7. survive refresh/direct query only when the requested view is an eligible alternative, otherwise fall back to original primary with a bounded notice;
8. never recalculate scores or erase selected answers/evidence.

## Copy contract

Primary summary:

> **Close alternative: {B}.** {B} received direct support from **{recorded observation}** and stayed close under this reading’s relative comparison rule. It is a comparison path, not a second diagnosis or a claim of semantic adjacency.

Alternative view:

> **Comparing {B} with your original {A} reading.** This view reuses the same answers; it does not replace or rescore the original result.

No eligible alternative:

> Omit the slot. Do not render “No adjacent fits saved yet,” a color fallback, or a retake prompt solely to fill space.

## Compatibility

- Keep `adjacent_matches` name, array shape, rank fields, reasons, shares, and order internally.
- Keep `switchAdjacentView()`/URL compatibility during Gate A; UI labels and eligibility guards may change additively.
- Preserve Maze `sourceFaction`, `fit`, placement result, return URL, and return-to-primary behavior.
- Preserve dossier/recommendation/deck-link inputs; only public labels/qualification change.
- Existing legacy requests for a non-eligible `view` resolve safely to the primary; data is not rewritten.

True semantic adjacency, broader related-identity exploration, or rank-three presentation is excluded from Gate A.
