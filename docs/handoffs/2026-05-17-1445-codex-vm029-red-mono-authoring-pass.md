## Why it changed

Red existed only as an inactive identity shell. To match the White/Black/Blue practical mono bar, Red needed authored identity data plus model authoring so the adaptive engine could identify mono-Red directly instead of leaning on Rakdos, Gruul, Izzet, Prismari, or Boros evidence.

## Decisions made

- Kept the pass source-first: Red authoring lives in `data/identity-layers.json` and `research/build-faction-artifacts.mjs`; generated runtime artifacts were produced by `npm run build:factions`.
- Distinguished mono-Red from:
  - `BR`: cruelty, transgression, pain-as-spectacle, sacrifice-for-value.
  - `RG`: instinct, wildness, growth-through-force, primal belonging.
  - `UR` / Prismari: crafted expression, experimentation, spellcraft, performance-through-technique.
- Verified Red Commander Compass choices against the local Scryfall commander index before adding them.
- Added only one dossier guidance data entry in `assets/js/commander-dossier.js`; no presenter behavior was rewritten.
- Did not change placement scoring semantics, adjacent-fit presentation, discovery-path contracts, Green, or broader mono cleanup.

## Risks / uncertainties

- Existing source-land warnings remain in dossier audit output; they are unrelated to Red and predate this mono pass.
- Red evidence is overlap-sensitive and should stay narrow in future tuning so Rakdos, Gruul, Izzet, and Prismari keep their pair identities.
- Green should follow the same source-first pattern, with its own overlap audit.
