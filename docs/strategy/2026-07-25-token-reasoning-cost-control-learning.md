# Token Reasoning Cost Control - Permanent Learning

Date: 2026-07-25
Grounded in: VM-541, post-CRIT-001 governance cleanup, Token And Reasoning Cost Control policy

## Learning

Efficiency is useful only when it is subordinate to correctness and governance. Token discipline should reduce repeated context retrieval, unnecessary tool calls, and over-broad analysis, but it must never become permission to skip required validation, source-authority checks, review gates, Kanban updates, handoffs, or protected workflow controls.

Centralizing the policy prevents governance sprawl. A single canonical reference plus short pointers in active instruction surfaces is easier to maintain than repeated long-form rules across every prompt.

Optional recording beats mandatory ceremony. Efficiency or escalation notes belong in handoffs only when they explain a meaningful choice: deliberately deeper review for high-risk work, or intentionally narrow handling for low-risk work.

## Operating Consequences

- Default to proportionate reasoning and targeted checks.
- Escalate reasoning only for high-risk, conflicting, protected, or explicitly deep-review work.
- Keep CRIT, source-authority, MTG factual, migration, destructive-change, review-gate, testing, Kanban, and handoff requirements intact.
- Prefer one canonical policy document and compact references over duplicated governance text.
- Record efficiency decisions only when they materially help the next agent understand the work.
